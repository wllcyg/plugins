核心自动滚动与无缝切片缝合算法

在滚屏截图过程中，浏览器需要精准调度页面步进（`window.scrollTo`），并基于 `devicePixelRatio` 严格计算 Canvas 物理像素映射，确保每一张切片在垂直轴上不漏 1 像素，亦不重叠 1 像素。

core-screenshot-engine.ts TypeScript 5.x 
const stitchAndDownload = async (slices: ScreenShotSlice[], contentWidth: number, totalHeight: number, dpr: number) => {
  // 1. 创建精确物理分辨率的高清画布 (支持 2x 矢量级 Retina)
  const canvas = document.createElement('canvas');
  canvas.width = Math.round(contentWidth * dpr);
  canvas.height = Math.round(totalHeight * dpr);
  const ctx = canvas.getContext('2d');

  // 2. 精准消除右侧滚动条占用，并执行源/目标视口缝合
  for (const slice of slices) {
    ctx.drawImage(slice.image, 0, slice.sourceY * dpr, contentWidth * dpr, slice.sourceHeight * dpr, 0, slice.y * dpr, contentWidth * dpr, slice.sourceHeight * dpr);
  }
};

关于高清长截图的核心疑问

Q1：为什么生成的 2x 高清图文字放大后依然极致锐利？
答：因为我们没有采用简单的 Canvas 拉伸位图放大，而是使用浏览器底层渲染引擎的 `setZoom(2.0)`，让浏览器内核按 200% 物理像素对文字矢量和 SVG 重新光栅化重绘，真正做到了矢量级高清输出。
Q2：为什么右侧的原生滚动条彻底不会出现在截图中？
答：我们实施了「双重保险」——一方面截屏时通过动态注入 CSS 隐藏原生滚动槽；另一方面 Canvas 在拼接时强制按照 `clientWidth` 精确裁剪右侧边缘，物理层面杜绝任何滚动条像素被画入。
Q3：截取时遇到最后一屏不满一整屏的高度，会发生重叠错位吗？
答：绝不会。算法会自动计算最后一屏与上一屏的 `overlap` 重叠像素差值，在绘制最后一张切片时精确裁掉顶部多余的重叠区域，保证接缝处严丝合缝。
